# Linux Log Analyzer 🐧

**A lightweight Python command-line tool for exploring Linux and application logs.**

[![Python](https://img.shields.io/badge/Python-3.10%2B-3776AB?logo=python&logoColor=white)](https://www.python.org/)
[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)

A small, testable portfolio project demonstrating Python, regular expressions, log parsing, streaming data analysis, JSON reporting, and CLI design. The tool uses **only Python's standard library at runtime**.

## Features

- Parse timestamped application logs and traditional Linux syslog lines.
- Automatically detect the supported format **on each line** in a mixed file.
- Summarize severity levels, service names, and daily log volume.
- Filter by date range, one or more severity levels, service name, and message text.
- Print a human-readable summary or machine-readable JSON.
- Stream input line by line, avoiding loading entire logs into RAM.
- Count malformed/unsupported lines instead of silently treating them as valid.
- Run automated tests using Python's built-in `unittest`.

## Requirements

- Python **3.10 or newer**; Linux, macOS, or Windows.
- No third-party runtime dependencies.

## Quick start

From the project directory, run without installing anything:

```bash
python -m log_analyzer examples/sample.log --syslog-year 2026
```

Alternatively, install the CLI locally:

```bash
python -m pip install .
linux-log-analyzer examples/sample.log --syslog-year 2026
```

Try common filters:

```bash
# Find ERROR and CRITICAL events on a particular day
python -m log_analyzer examples/sample.log --since 2026-10-18 --until 2026-10-18 --level ERROR --level CRITICAL --syslog-year 2026

# Explore logs generated by the auth service
python -m log_analyzer examples/sample.log --service auth

# Find messages containing the word "slow"
python -m log_analyzer examples/sample.log --contains slow

# Export structured summary to a JSON file
python -m log_analyzer examples/sample.log --json --syslog-year 2026 > report.json
```

## Supported formats

**Application logs**, with a full date, explicit severity and a service name:

```text
2026-10-17 09:00:01 ERROR auth Invalid credentials
2026-10-17T09:00:01 [WARN] api: Slow response
```

Supported severity names: `TRACE`, `DEBUG`, `INFO`, `WARN`/`WARNING`, `ERROR`, `CRITICAL`/`FATAL`.
The tool normalizes `WARNING` to `WARN` and `FATAL` to `CRITICAL`.

**Traditional syslog**, with month/day, time, host and service:

```text
Oct 18 10:10:03 workstation sshd[4242]: Accepted connection
```

Traditional syslog lines **do not include a year or an explicit severity**. Use `--syslog-year 2026` to select a year (default: the current year). Such lines are classified as `UNKNOWN`, **not** guessed as `INFO` or `ERROR`. A file spanning New Year's Day may require pre-processing, since one year is applied to all traditional syslog lines.

**Limitations:** The parser intentionally does not handle journald's binary journal, Apache/Nginx access logs, multiline stack traces, or every syslog variant. Invalid or unsupported lines are counted in `skipped_lines`. The app parser expects second-resolution timestamps (no timezone offset or fractional seconds).

## CLI options

| Option | Purpose |
| --- | --- |
| `file` | Path to the log file (required) |
| `--format auto\|app\|syslog` | Choose parser; auto detects per line (default) |
| `--syslog-year YEAR` | Set year for traditional syslog entries |
| `--since YYYY-MM-DD` | Include entries from this date (inclusive) |
| `--until YYYY-MM-DD` | Include entries through this date (inclusive) |
| `--level LEVEL` | Match a severity; repeat to select several |
| `--service NAME` | Exact case-insensitive service match |
| `--contains TEXT` | Case-insensitive substring search within messages |
| `--top-services N` | Number of services to display in text mode (default: 5) |
| `--json` | Print structured JSON |
| `--help` | Display full help |

`total_lines`, `parsed_lines`, `skipped_lines`, and `format_counts` describe **all** input lines, before filters. `matched_lines`, severity counts, service counts, date counts, and first/last matches are calculated **after** filters.

## Privacy and safe usage

Logs may contain IP addresses, usernames, tokens, or other sensitive information. The analyzer **reads files locally** and summarizes counts; it does not upload your logs or print raw message bodies in normal reports. The supplied example is synthetic. Avoid committing real production logs or sensitive generated reports.
